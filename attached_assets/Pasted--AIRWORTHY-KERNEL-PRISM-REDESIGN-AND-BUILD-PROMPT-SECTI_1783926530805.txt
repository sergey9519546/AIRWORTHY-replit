## SECTION 1 — INSTALL THE KERNEL+PRISM OPERATING RULES

You will follow the KERNEL+PRISM framework throughout this AIRWORTHY project.

### KERNEL rules

Apply these rules to every step:

- **K — Keep it simple:** Each step has one clear goal.
- **E — Easy to verify:** Every output must include objective success criteria.
- **R — Reproducible:** Base decisions on the existing repository, named references, explicit requirements, and documented evidence.
- **N — Narrow scope:** Do not combine unrelated work into one step.
- **E — Explicit constraints:** State what must be done and what must not be done.
- **L — Logical structure:** Every task uses:
  1. Context
  2. Task
  3. Constraints
  4. Output format
  5. Verification

### PRISM rules

Before each major task, restate:

- **P — Purpose:** What this step produces and why it matters.
- **R — Reusable parts:** What systems, components, or rules can be reused.
- **I — Inputs:** Which files, repository sections, prior outputs, and references are being used.
- **S — Segments:** The exact output sections.
- **M — Method:** How the result will be verified.

### Execution rules

- Do not jump directly into visual styling.
- Do not redesign before understanding the current repository.
- Do not combine audit, strategy, implementation, and validation into one vague pass.
- Complete every verification step before proceeding.
- When a verification check fails, fix the problem and rerun the check.
- Preserve working product logic unless there is a documented reason to change it.
- Do not replace the current framework without a strong technical justification.
- Do not stop at recommendations, wireframes, or written descriptions.
- Implement the approved redesign in the existing project.
- Do not declare completion while buttons, routes, states, or interactions remain incomplete.

# SECTION 3 — PRODUCT DEFINITION

## Core product

AIRWORTHY estimates how much a residential property could earn when operated as a short-term rental.

The primary user job is:

> Enter a property and understand how much it could realistically earn as a short-term rental.

AIRWORTHY is not primarily:

- A mortgage calculator
- A property brokerage
- A generic investment dashboard
- A property-management platform
- An aviation-themed interface
- A luxury-property marketing website
- A general-purpose AI analytics platform

Do not broaden the product into unrelated real-estate features.

## Primary promise

Use this core positioning:

> See what any property could earn.

Supporting explanation:

> Estimate short-term-rental revenue using comparable listings, local demand, occupancy patterns, seasonality, and nightly pricing.

Primary action:

> Estimate earnings

## Product hierarchy

Every interface should prioritize information in this order:

1. Property
2. Estimated annual revenue
3. Revenue range
4. Most likely revenue
5. Monthly earning pattern
6. Average nightly rate
7. Expected occupancy
8. Comparable evidence
9. Estimate confidence
10. Performance drivers
11. Editable property assumptions
12. Secondary market information

Revenue must remain the dominant result.
