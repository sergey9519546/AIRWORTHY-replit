## The previous direction was wrong

The last concepts were essentially:

> Luxury property photograph + dark dashboard + gold accents + KPI cards.

That is a familiar real-estate template, not a defensible product identity. The main problems were:

* **Black and gold communicated generic “luxury,” not intelligence or trust.**
* The mansion dominated the experience while the actual product remained secondary.
* Every metric was placed inside a card, producing visual noise and weak hierarchy.
* The map consisted of decorative revenue markers rather than a clear analytical workflow.
* The property page showed numbers without explaining **confidence, assumptions, comp quality, or risk**.
* The aviation idea was expressed through logos and styling instead of the product logic.

AirDNA already uses **Rentalizer** for its property earnings product and already provides revenue, ADR, occupancy, financial calculations, and comparable-property analysis. Recreating those same screens with a darker palette would only make AIRWORTHY look derivative. ([AirDNA][1])

---

# Correct Product Positioning

AIRWORTHY should not be presented as another “Airbnb calculator.”

It should be positioned as a **property-readiness and investment-certification system**:

> **Determine whether a property is AIRWORTHY before you buy, list, or operate it.**

The name becomes meaningful when the application produces a clear decision:

* **CLEARED** — strong projected performance
* **CONDITIONAL** — viable under specific assumptions
* **EXPOSED** — financially sensitive
* **GROUNDED** — insufficient earnings potential

Aviation should influence the **decision system**, not decorate the interface. No airplane icons, wings, compass logos, cockpit gauges, or runway graphics.

---

# New Creative Direction

## Architectural Editorial × Precision Instrumentation

The visual system should feel like:

* A high-end architectural publication
* A professional underwriting report
* A modern geospatial intelligence platform
* A calm, focused analytical instrument

Linear’s redesign work emphasizes reducing noise, creating a calmer interface, and preserving focus as product complexity grows. That is a much stronger reference than generic SaaS dashboard galleries. ([Linear][2])

Mapbox’s real-estate guidance also supports making the map part of the brand: remove irrelevant default POIs, control marker visibility, prioritize meaningful layers, and create a map style that does not look like every Google Maps implementation. ([Mapbox][3])

# AIRWORTHY Visual System

## Palette

Avoid navy and gold.

| Role             | Color                         |
| ---------------- | ----------------------------- |
| Primary canvas   | Mineral white `#F2F0E9`       |
| Secondary canvas | Bone `#E8E5DC`                |
| Primary ink      | Carbon `#111310`              |
| Secondary text   | Graphite `#686A64`            |
| Positive signal  | Electric chartreuse `#C9FF45` |
| Warning signal   | Runway orange `#FF623F`       |
| Analytical blue  | Atmospheric blue `#4968FF`    |
| Dark map         | Near-black green `#111713`    |

Chartreuse should appear only on selected properties, active controls, and positive status signals. It becomes recognizable because it is scarce.

## Typography

* **Primary:** disciplined contemporary grotesk
* **Data:** compact monospaced face
* **Editorial emphasis:** one restrained serif used only for major statements
* Large numerals, narrow metric labels, generous whitespace
* Sentence case rather than uppercase everywhere

## Interface Geometry

* Fewer cards
* Thin structural rules instead of containers
* Large uninterrupted surfaces
* Slightly squared 8–12 px radii
* No excessive glassmorphism
* No shadows unless indicating physical elevation
* Strong alignment to a 12-column architectural grid

# Page 1 — Cover / Revenue Check

## Central idea

The landing page should resemble an immediate property inspection—not a marketing page with a decorative house photograph.

### Above the fold

**AIRWORTHY**

# Is this property

# ready to perform?

`Enter an address to inspect its short-term rental potential`

Large address command field:

> 2209 Ridgeway Drive, Austin, Texas

Primary action:

> **Run property check →**

Below it, a live product preview should already show:

```text
AIRWORTHY STATUS
CONDITIONAL

Expected annual revenue
$78,400 — $94,100

Confidence
High · 31 verified comparables
```

The property image appears as a restrained architectural crop or aerial parcel photograph. Data overlays feel embedded into the photograph rather than placed in floating cards.

### The hero should communicate

1. The property
2. The verdict
3. The expected earnings range
4. The reliability of that estimate
5. The next decision

Not feature lists, fake partner logos, four equal benefit cards, and a testimonial.

# Page 2 — Map Search

## Layout

The map occupies approximately **80% of the screen**.

A narrow contextual rail changes depending on the selected workflow. It is not a permanent filter warehouse.

### Top command bar

```text
Austin, TX                       Revenue ▾    3 BR ▾    Entire home ▾
```

### Map modes

Only one primary layer should be active at a time:

* Revenue potential
* Occupancy strength
* ADR
* Seasonality
* Supply pressure
* Regulation exposure
* Investment resilience

TopHap and other Mapbox real-estate implementations demonstrate the usefulness of property layers, market filters, parcel context, and comparative analytics, but AIRWORTHY should simplify those capabilities into a more accessible workflow. ([Mapbox][4])

### Map behavior

Do not scatter `$92K`, `$67K`, and `$31K` bubbles everywhere.

Use:

* Quiet parcel shading at the market level
* Revenue clusters when zoomed out
* Individual property markers only when sufficiently zoomed in
* A single high-contrast selected property
* Automatic decluttering
* Neighborhood boundaries that appear contextually
* A restrained legend integrated into the map

### Selected-property dock

A horizontal inspection dock emerges from the bottom:

```text
2209 Ridgeway Drive

AIRWORTHY 82 / 100
CLEARED

$78.4K–$94.1K projected revenue
67% occupancy · $237 ADR
31 matched comparables

[Inspect property]
```

This keeps the user on the map rather than opening large floating cards over it.

# Page 3 — Property Intelligence Report

This page should feel like a professional decision brief, not another dashboard.

## Opening section

```text
2209 Ridgeway Drive
Austin, Texas

AIRWORTHY STATUS
CONDITIONAL

The property can support a strong short-term-rental
strategy, but projected performance depends heavily
on weekend pricing and pool-season demand.
```

### Primary metrics

The central number should be a **range**, not false precision:

# $78,400–$94,100

**Expected annual gross revenue**

Supporting data:

* Central estimate: `$86,200`
* Confidence: `High`
* Comparable quality: `31 of 44 accepted`
* Forecast horizon: `Next 12 months`
* Data recency: `Updated 6 hours ago`

Mashvisor and AirDNA establish revenue, occupancy, ADR, NOI, cap rate, and comp analysis as expected category capabilities. AIRWORTHY must differentiate itself by showing why the estimate should be trusted and where it could fail. ([Mashvisor][5])

## Report hierarchy

### 1. Decision summary

A one-paragraph explanation of the verdict.

### 2. Earnings envelope

A probability band showing:

* Conservative case
* Expected case
* Strong case
* Downside threshold

Not a generic twelve-bar chart.

### 3. Performance drivers

```text
+ Pool increases summer ADR
+ Four-bedroom inventory is limited nearby
+ Walkability supports weekend occupancy
− Revenue falls sharply below 58% occupancy
− Local supply is growing faster than demand
```

### 4. Comparable evidence

Each comparable receives:

* Match score
* Distance
* Bedroom and guest-count match
* Amenity difference
* Revenue
* ADR
* Occupancy
* Include/exclude control
* Reason for inclusion

### 5. Scenario laboratory

The user can adjust:

* Occupancy
* ADR
* Cleaning fees
* Management fees
* Platform fees
* Operating expenses
* Seasonality
* Property improvements

The revenue range and status update immediately.

### 6. Decision footer

```text
AIRWORTHY VERDICT

Proceed only if acquisition and operating costs remain
below the modeled break-even threshold.

[Save analysis] [Compare another property] [Export report]
```

# Distinctive Brand Device

AIRWORTHY needs one visual behavior that belongs only to AIRWORTHY.

## The Earnings Envelope

Instead of generic bars and line charts, every property receives a horizontal forecast field:

```text
DOWNSIDE          EXPECTED RANGE               UPSIDE
───────────────████████████████████──────────────────
$61K             $78K          $94K             $108K
```

The field changes as assumptions, comps, and market conditions change.

It becomes:

* The hero visual
* The property-page visualization
* The comparison visualization
* The saved-property thumbnail
* The report-cover graphic
* The core brand motif

Mercury’s recent design work provides a useful broader lesson: premium products become recognizable when their data is given a visual expression that could not simply be transferred to another company. ([Mercury][6])

# What Must Be Removed From the Next Design

* Black-and-gold luxury styling
* Giant mansion as the primary hero
* Generic abstract hexagon logo
* Four identical feature cards
* Floating map-price bubbles everywhere
* Tiny text inside a three-screen montage
* Random AI sparkle icons
* Fake platform-partner logos
* “Trusted by 12,000+ investors” filler
* Every statistic placed inside a rounded rectangle
* Decorative charts that do not support a decision
* Unqualified “98% accuracy” claims
* Aviation-themed visual clichés

# Correct Generation Strategy

Do not generate another collage containing three miniature pages.

The stronger route is:

1. **Full-resolution cover page**
2. **Full-resolution map workspace**
3. **Full-resolution property intelligence report**

All three should share one design system, one navigation model, and one decision hierarchy. The first screen to develop should be the **cover page with the live AIRWORTHY inspection preview**, because that establishes the identity the map and report must inherit.

For implementation, include `Organization`, `SoftwareApplication`, `WebSite`, and relevant `FAQPage` schema code at the end of the web app.
